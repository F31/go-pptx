## COV-04 覆盖率门槛回归（ADR-018 Tier 2 第二处同源缺陷）
- **发现**：例行全仓覆盖率复核发现 `internal/opc` **89.5%**（登记值 90.0%），跌破 COV-04 的 90% 门槛。
- **归因（worktree 隔离实测）**：`f7c8dad`（Tier 2 之前）90.4%/90.5%；`27a539d`（Tier 2 已落地、ADR-024 未修复）89.6%；HEAD 89.5%/89.6%。→ **降幅由 Tier 2 引入（−0.8pp）**，ADR-024 的结构调整无额外影响。**Tier 2 自 `752fb95` 落地即跌破门槛，三天无人发现**。
- **根因**：`tryRawCopyOriginal` 的 4 条安全门限拒绝分支零测试覆盖（该函数覆盖率仅 73.1%）。
- **修复（零生产代码改动）**：新增 `internal/opc/saveplan_raw_guard_test.go`
  - `TestTryRawCopyOriginalSafetyGate`：8 case 表驱动（合格 Store / `.xml` / `.rels` / 缺失 Part / method 99 / 加密位 / data-descriptor 位 / 声明尺寸 0）+ 断言"被拒帧不得在输出注册任何条目"
  - `TestSavePlanWriteFallsBackOnUnsafeFrame`：data-descriptor 帧端到端验证回退路径
  - 3 项写入错误注入（raw 直通 / 流式回退 / `zip.Close` flush）
- **结果**：`internal/opc` 89.5% → **90.3%**（corpus 89.6% → **90.5%**）；全仓 total 84.4% 不变。
- **守门有效性**：注入验证（临时删加密位门限）→ `reject-encrypted-frame` 必红（`raw = true, want false`），已还原（`saveplan.go` 零 diff）。

### 关键构造技巧（可复用）
- `zip.Writer.Create` 产出的条目**天然带 flags bit3**（Go 用 data descriptor 回填尺寸）→ 合成包条目全部被 Tier 2 门限拒绝 → 这**正是"不安全帧"的真实形态**，可直接用于回退路径测试。
- 反之，要产出**可 raw 直通**的帧必须用 `CreateRaw` + 显式 `CompressedSize64`/`UncompressedSize64`（Tier 2 现有测试即如此构造）。
- `zip.Writer` **无法**产出"未知 method / 置位加密位 / 声明尺寸 0"的帧 → 必须手工拼 ZIP（新增 helper `rawHdrZip`：local header + central directory + EOCD，可精确控制 method/flags/size）。
- 空 ZIP 的 EOCD 固定 22 字节 → 断言"未注册条目"必须解析 `zr.File` 计条目数，**不能**断言字节长度。
- 手工构造 `.rels` 条目时内容必须是合法关系流（用 `miniRels("")`）；乱写会被 `Load` 判 malformed。

### 教训
- **Tier 2 的两处缺陷同源**：落地时只跑 build/test/vet，**既没跑 B1 端到端保存校验（→ 漏掉重复条目），也没跑覆盖率门槛（→ 漏掉门限分支零覆盖）**。性能/IO 改动的完成定义必须含这两项。
