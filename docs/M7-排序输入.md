## 1. 排序输入基线

### 1.1 方案 §2.4 创新方向（护城河 / 创新方向 / 不做清单 / 立项过滤器）

> M7 创新扩展阶段：能力 manifest 工具链、WASM 浏览器检查工具、动画时序只读 IR、模板数据绑定引擎。逐项独立验收，依赖底座工作包通过后方可立项。

能力报告 → manifest 工具链（**CAP-01**）是 §2.4 护城河第 2 项（"调用方实现能力感知降级与编排集成"）的工具化交付；TOOL-02 把只读 CLI 编译为 WASM（浏览器原生检查工具）；TIMIR-01 是 §2.4 创新方向"动画时序只读 IR"；TPL-01 是 §2.4 创新方向"模板数据绑定引擎"。

### 1.2 实施计划 §12 M7 段

> CAP-01（capability manifest 导出与 JSON schema、六维状态与 SaveReport 一致、`pptx capability` 命令）→ TOOL-02（WASM 编译目标 + 静态网页只读检查工具，文件不出本地设备）→ TIMIR-01（动画时序只读 IR：opaque node 标记 + 诊断，估计值不得作为 AdvanceAfter 计算输入）→ TPL-01（模板数据绑定，ADR 013：构建在保真补丁与跨 Run 替换之上，绑定失败显式报错且无部分写入）。

→ §12 候选排序与 §2.4 创新方向直接对应（CAP-01→TOOL-02→TIMIR-01→TPL-01），本节作为预排基线。

**预排结论**（在语料到位回填前的**临时排序**，每项工作包独立验收，可裁剪）：

| 序 | WP | 设计基线首选命中 | §12 候选位 | 立项过滤器（§2.4） | 预估承载能力 | 备择触发条件 |

| 1 | **CAP-01** capability manifest 与 JSON schema | ✅ 护城河第 2 项 | §12 第 1 位 | 底座已通过（TOOL-01）；不引入新解析路径 | `pptx capability` CLI、六维能力报告、JsonManifest schemaVersion=go-pptx.capability/1.0、与 SaveReport 同事实来源 | — |

### 2.1 预排风险

- **设计基线覆盖率为 4/4**：CAP-01/TOOL-02/TIMIR-01/TPL-01 均直接命中 §2.4 创新方向与 §12 候选位，**预排与方案完全对齐**。
- 当前没有语料，**预排仍可被语料回填推翻**（特别是 TPL-01 绑定语法的实际选择上）；§13"进入前重估"机制可保留调整窗口。TPL-01 首版语法（`{{path}}` / `{{#if}}…{{/if}}` / `{{#each}}…{{/each}}` / 图表按形状名绑定）已固定并经 20 项单元测试确认，语料回填后可扩展但保持向后兼容。
- CAP-01 与 TIMIR-01 之间存在隐含的"能力协商"链路：CAP-01 的六维状态会包含 TIMIR-01 标签；TIMIR-01 已落地，capability manifest 的 `animation.timing_ir` 由 Partial（空 childTnLst 边缘 case）升级为 **Supported**（2026-09-10，xmlstore 重写解析器彻底消除 std 自闭合 cond 同步偏差；Limits 仅保留"未识别子元素落记为 OpaqueNode"这一语义级承诺）。

### 2.2 重排触发条件

任一情况即重排：

1. 语料回填：testdata/corpus/ 样本累计 ≥ 10 份后扫描 capability manifest 与时序 IR 输出在调用方的实际使用率，更新排序。
2. 重大客户端反馈：浏览器侧 WASM 实测发现某子命令需要补充或调整顺序。
3. 依赖阻塞：WP 前置（如 TIMIR-01 需要新增 IR Schema 字段）需要重新分批。
4. 方案变更：新增 R 档特性走 ADR，按 §12 §R7 缓解。
