## 1. 规划范围与目标

### 1.1 范围

- 按方案 16 章覆盖 M0–M8 全阶段交付；M0–M5 为确定排期区，M6–M8 为估列区（进入前重估，见 §13）。
- 六项产品主线全部纳入：通用读写、可控保真编辑、精细格式、自动讲解、工程可靠性、可选扩展。
- V2.6 新增项纳入对应阶段：docProps 元数据读写（5.1，P0，M2）、无障碍 AltText/IsDecorative（8.1，P1，M2）、M6 七个工作包 GEOM-02/STYLE-02/LAYOUT-01/ANIM-02/VIDEO-01/CHART-02/TEXT-03（M6）、WASM 可编译性 CI（26 章，P1，自 CORE-01 起）。
- 未决项不进本期排期：ADR 015（只读并发快照，候选未采纳）、讲稿标记语法子包（候选，待专项评审）。

### 1.2 不在范围内（维持方案 2.4"明确不做"）

完整动画编辑、像素级渲染复刻、chartEx 现代图表、SmartArt 布局、Strict 格式语义写入、宏写入、二进制 .ppt、加密文件写入。范围外需求一律以 ErrUnsupported* 显式返回，不静默降级。

### 1.3 成功标准

- 里程碑目标：**M0–M2 形成首个可用 MVP**（模板编辑闭环）；**M0–M5 形成可发布组件**（22–38 人周）。
- 闭环验收：闭环一"模板打开 → 读取讲稿 → 更新文本/备注 → 保存"；闭环二"音频嵌入 → 计时 → 放映"（方案 1.2）。
- 发布硬门槛按方案 15.3 执行（详见 §9）。
- 每个已声明能力必须由测试证据支持，禁止以"接口已定义 / XML 已生成"作为完成标准（方案 24 章）。

## 3. 总体实施策略

1. **保真底座先行、垂直验证前置**：xmlstore 词法保留（XML-01/02）是最高风险基础工程。开工第 1–2 周即完成"含未知扩展与动画的页面，仅修改一个普通文本 Run，验证其余节点和相关 Part 不变"的垂直验证（方案 4.3）。**失败则先调整保存方案，禁止在上层功能建立于不可保真的底座上**（方案 16 章）。
2. **阶段门禁制**：每个里程碑设置退出标准（§6），未通过不得进入下一阶段；允许 M4 在 M2 后按业务优先级前移，但不能绕过计时保留验证。
3. **语料与金样驱动**：QA-01 从第 1 天开始，与功能开发并行。每个原生样本保留修改前后金样，同一文件可命中多标签；M6 排期与 R 档特性优先级由语料频率统计驱动。
4. **设计态/验证态严格分离**（V2.6 §15.3 说明）：方案矩阵档位与测试规格是"目标"不是"已实现"；周报、发布声明只允许引用已验证的通过数/样本数，能力矩阵"目标档位"列不得当作验证结论输出。
5. **证据包制**：每项 E/F 档承诺、每个客户端关键用例，交付"原始 PPT + 操作参数 + 预期报告 + commit + 工具链 + 客户端版本 + 截图/播放记录"证据包（方案 25 章）。
6. **双轨并行**：功能轨（M0→M5 主线）+ 兼容轨（语料整理、客户端验证、fuzz、回归），兼容轨不阻塞功能轨开发但阻塞发布。

## 6. 里程碑详规与退出标准

### M0 技术验证（约 2–3 人周）

**目标**：证明"精确补丁 + 未修改 Part 透传"的保存底座成立。

| 任务 | 说明 |
|---|---|

| QA-01 起步 | 收集 20–30 份样本（最小结构 + 真实文档，尽量覆盖 PowerPoint/WPS/LibreOffice 及含动画/未知扩展的样本）；记录来源、许可、生成器版本、字体环境；建立"修改前/后金样"存储约定与特性双标签索引 |
| OPC-01 | ZIP 条目索引、PartName 与路径分离、资源预算（默认 10k 条目/单 XML 32 MiB/总解压 1 GiB/深度 256）；重复条目、越界路径、超限测试 |
| XML-01 | 命名空间感知解析与原始跨度；前缀作用域、未知子树、`mc:AlternateContent`/`mc:Ignorable` 上下文保留；非 UTF-8 拒绝语义编辑 |
| XML-02 | 文本/属性补丁（区间降序应用、重叠冲突检测、XML 转义、空白属性）与受控结构插入 |
| M0 垂直验证程序 | 对含动画与未知扩展的页面仅修改一个普通文本 Run → 保存 → 逐 Part 哈希比对（B1）+ 同节点未知区字节不变断言 |

**退出标准**：垂直验证全绿；B1 报告输出可用；AT-01（不修改保存：未修改 Part 哈希一致）、AT-14（恶意包在预算内失败、无 panic 无文件逃逸）通过；语料 ≥20 份且许可记录齐全。

## 11. 工程基建与开发规范

- **仓库**：单 Go module；根包 `pptx`；低层存储 internal（opc/xmlstore/edit/style/textmap/geom/validate）；render、cmd/pptx、testdata/corpus、docs 按方案 §3 建目录。
- **工具链**：建仓时选定受支持 Go 稳定版本写入 go.mod/toolchain；CI 验证最低版本与当前版本；核心构建 `CGO_ENABLED=0`；**每次发布 CI 执行 `GOOS=js GOARCH=wasm` 编译核心包**（V2.6 §26 P1）。
- **依赖纪律**：标准库优先（archive/zip、encoding/xml、io、context、sha256）；第三方依赖清单 + 替代方案记录。
- **编码规范**：普通错误返回 error 不 panic；不以 nil 掩盖不支持能力；不用吞错误的链式 Setter；零值语义写入 GoDoc（时间/单位/资源限制的零值不得解释为"无限"）；属性与单位集中换算，禁止全包混用 float64。
- **命名与引用**：新 Part 名称按类型前缀 + 查重序号；rId/ShapeID/节点 ID 各自作用域查重，不为美观全量重排；删除未知依赖时拒绝操作而非静默删除。
- **ADR 流程**：架构决策按方案 17 章追加 ADR；矩阵档位、保存语义、并发模型的变更必须记录。
- **代码评审关注点**：是否绕过 xmlstore 直接改 XML、是否整树 Unmarshal→Marshal 重建、是否用正则定位 XML、是否覆盖整个 timing 树、是否静默丢弃未知内容。
