## 1. 起点状态（2026-09-12 实测）

### 1.1 公共 API 与稳定性
- v1.0 冻结：**34 Stable 段落（33 type + 1 哨兵聚合段）/ 50 Stable 符号 / 5 Experimental / 120 API type / 158 总 type**
- 演化原则：仅追加新方法/字段，不破坏已有签名（详见 ADR-015 §"v1.0 冻结清单"+ v1.0-freeze-list §D 评审 checklist）
- 实验段（5 段）允许 1.x 内调整接口，但需更新 godoc 演化边界声明

### 1.2 质量门（2026-09-12 下午实测）

| 全包加权覆盖率 | 84.4% | 持续 ≥ 84.5% | 守住 |

| L3 客户端矩阵 | 8/8（PowerPoint 16.0.20326 + WPS 12.1.0.28599 × 4 样本）| 扩展更多客户端/平台 | 可选 |

| CI 交叉构建 | 4 目标（js/wasm + darwin/arm64 + wasip1/wasm + linux/arm64）| 扩展到 freebsd/riscv64 | 可选 |

## 2. 1.x 总体定位

### 2.1 设计哲学（继承 v1.0）
- **字节级保真**：未触碰区域恒等（v1.0 B1 收敛 ≤1 字节）
- **事务安全**：plan-then-apply，单事务提交，失败零残留
- **三层 API 承诺**：Stable / Experimental / 默认 API 分级清晰
- **零运行时依赖**：CGO=0 + 单二进制 + WASM 可编译

### 2.2 1.x 期间允许的演化
- **可加**：新公共方法（不破坏已有签名）、新 Experimental 段
- **不可加**：现有 Stable 段签名变更、删字段、改 Stable 哨兵（除非新 ADR 授权降档）
- **不可破坏**：B1 哈希金样、PERF-01 基线、L3 真机矩阵

### 2.3 路线图骨架（5 个候选方向）
按 v1.0 残余缺口 + 用户场景驱动，给出 5 个候选方向，本路线图按 A/B/C/D/E 编号：

| 方向 | 主题 | 工作量 | 价值 | 1.x 主推 |
|---|---|---|---|---|
| A | 架构 refactor（沿 ADR-016 路径） | M | 中 | ✅ 主线 |
| B | 覆盖率收尾（COV-04 5/6→6/6） | S–M | 中 | ✅ 主线 |
| C | v1.0.1 patch（今日累计变更打包） | XS | 高 | ✅ 短期（首发窗口） |
| D | 用户场景驱动的新能力 | L | 高（待识别）| 按需 |
| E | 客户端矩阵 + 分发扩展 | M | 中 | 可选 |

> 工作量：XS ≤1d / S ≤3d / M 1–2 周 / L >2 周

## 3. 候选工作包（按方向分组）

### 方向 A：架构 refactor（沿 ADR-016 续）

| 工作包 | 入口 | 退出标准 | 工作量 | 风险 |
|---|---|---|---|---|
| **A-1 chart 抽 `internal/chart`** | chart.go 1319 + chartadv.go 128 + chart_test.go 980 + chartadv_test.go (~140) | 根包只剩 facade；`internal/chart` 不反向 import 根；测试 100% 通过；B1 哈希金样不变 | M（1.5 周） | 中（接口广，最大文件） |
| **A-2 Shape capability 小接口拆分** | Shape 接口（已有 Geometry / Line / Fill / Effects / StyleMatrixRefs R 档 getter） | 新增 `GeometryProvider` / `FillProvider` 等小接口；现有 getter 仍保留；新增 caller 可选组合 | M（1 周） | 低（只新增，不破坏） |
| **A-3 internal/document 补编译期断言测试** | internal/document 42 行接口 | 至少 1 个 `var _ Foo = (*Bar)(nil)` 编译期断言或一份最小行为测试 | XS（0.5d） | 无 |
| **A-4 text.go 拆分候选** | text.go 1356 → text-core / text-replace / textnode 三组（不抽 internal，与 chart 不同路径）| 根包内文件按职责拆，跨文件职责清晰 | M（1 周） | 中（最复杂分支最多）|
| **A-5 bind.go 拆分** | bind.go 1179 行（plan + apply 两阶段 + 多种标记处理） | 拆分为 bind-plan / bind-apply / bind-marker 三组 | S（3d） | 中 |

**决策建议**：
- A-1 优先（最大 ROI，符合 ADR-016 演化原则）
- A-2 跟随 A-1（chart 抽出后，shape getter 群再拆）
- A-3 立等可取，归入 v1.0.1 patch
- A-4 / A-5 推迟到 1.x 中期，看用户反馈

## 4. 阶段划分（推荐）

### 阶段 1：v1.0.1 patch（短期，1 周内）
- C-1 v1.0.1 tag（必做）
- C-2 脚本目录收口
- C-3 已知小 bug 修复登记 ✅ **2026-09-12 落地**（[`docs/v1.0-bug-registry.md`](v1.0-bug-registry.md)）
- A-3 internal/document 编译期断言（附送，XS 工作量）

**退出**：v1.0.1 tag 推送，与 v1.0.0 binary-compat

> **2026-09-12 22:0x 实测**：阶段 1 全量落地——C-1 v1.0.1 tag 已推送（commit 9f24866）、C-2 脚本目录收口（C-1 patch release 周期内）、**C-3 [`docs/v1.0-bug-registry.md`](v1.0-bug-registry.md) 已建**、A-3 `internal/document` 接口编译期契约（commit 1915fc2）。实际版本已升至 **v1.0.2**（commit b9303a1 + tag v1.0.2），阶段 1 已被 v1.0.2 周期吸纳并扩展。

### 阶段 2：COV-04 全闭合（中期，1–2 周）
- B-1 opc 88.9%→90%（I/O 错误路径注入）
- B-3 root 82.8%→85%（按 value-per-test 排序的 30+ 系统测试，必要时拆 2 周）

**退出**：6 包低层格式 ≥90%、root ≥85%、全包加权 ≥85%

### 阶段 3：架构 refactor 主线（中期-长期，4–6 周）
- A-1 chart 抽 `internal/chart`（1.5 周）

### 阶段 4（可选）：分发扩展
- E-3 CI 多平台二进制（用户首问时分发版本时做）

- D-1 ~ D-5：用户报缺时启动，单独排期

## 5. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| A-1 chart 抽 internal 期间被 PR review 拒 | 1.x 阻塞 | 先开 ADR-017 chart-internal-extraction（参照 ADR-016 模板），提前对齐；chart.go 1319 行体量大、依赖广（workbook + data + labels + trendline + errorbars + axes + clone），拆前必须有充分行为测试 |
| A-2 Shape capability 接口命名引发 v1.x 性能回退 | 公开 type assertion 频次 | 用 optional getter + interface assertion 双轨，新 caller 走接口、已有走老方法 |
| B-3 root 85% 边际收益低 | 测试开发 1 周但仅 +2.2% 覆盖率 | 按 value-per-test 排序，必要时停在 84% 写"已 saturated"决策 |
| C-1 v1.0.1 binary-compat 失守 | 用户升级风险 | ~~严格限定 patch 仅含测试/文档/小修；不动公共 API 签名；CI 跑 v1.0.0 公共 API 断言（grep Stable 段落、字段数对齐）~~ → **已落地（2026-09-12）**：`api_surface_test.go` 用 `go/ast` 断言 158 type 名单 / 34 Stable 段 / 50 Stable 符号 / 5 Experimental / 17 哨兵（含错误字符串）/ **127 个 Stable 方法**，随 `go test` 进 CI |
| E-3 多平台分发引入 GH Release 自动化 | 工时 + 维护负担 | 先做 1.x 任一版本有需求时启动 |
| 所有方向共有：根包路径变更/导出符号变更破坏 v1.x 兼容性 | 用户升级中断 | freeze list §D 评审 checklist（升 Stable / 新增 / 降档）严格走 ADR 流程 |
