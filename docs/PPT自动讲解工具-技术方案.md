# PPT自动讲解工具 — 整体技术方案

> 目标:做一个类似 Murf AI 的产品——用户上传PPT，工具自动（或半自动）读取备注/正文生成AI配音讲解，最终可导出两种成品：
> 1. **带语音的PPT文件**（.pptx，每页嵌入音频，自动播放）
> 2. **讲解视频**（.mp4，画面+配音+可选字幕，一镜到底）

---

## 一、产品定位与核心场景

| 场景 | 说明 |
|---|---|
| 企业培训/内训 | HR或讲师做好PPT，不用真人录制即可生成标准化讲解 |
| 在线课程/微课 | 教师把讲稿写进备注，自动生成课程配音视频 |
| 销售/路演素材 | 销售把讲解词准备好，客户可自助观看配音版PPT |
| 无障碍/多语言 | 同一份PPT自动生成多语言配音版本，服务国际团队 |

**核心用户旅程**：上传PPT → 系统提取每页文本/备注 → 用户编辑/校对讲稿 → 选择音色和语言 → AI生成配音 → 预览调整时长/停顿 → 导出（PPT或MP4）

## 二、总体技术架构

```
┌─────────────────────────────────────────────────────────────────┐
│                          前端 (Web App)                          │
│   React/Next.js + 编辑器(讲稿/时间轴) + 播放预览器                  │
└───────────────────────────┬───────────────────────────────────────┘
                             │ REST / WebSocket
┌───────────────────────────▼───────────────────────────────────────┐
│                        后端 API 网关层                             │
│           Node.js/FastAPI + 鉴权 + 任务队列(Celery/BullMQ)         │
└──────┬───────────────┬───────────────┬───────────────┬────────────┘
       │               │               │               │
┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐
│  PPT解析服务  │ │  TTS语音服务 │ │  音视频合成  │ │  存储与CDN   │
│ python-pptx  │ │ 多引擎适配层  │ │  服务(渲染)  │ │  对象存储    │
│ 提取文本/备注 │ │ Azure/         │  FFmpeg      │  S3/OSS/COS  │
│ /版式/图片   │ │ ElevenLabs/  │ │  LibreOffice │ │  + CDN分发   │
│              │ │ edge-tts等   │ │  渲染帧      │ │              │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
```

### 2.1 前端层
- 框架：React/Next.js（或 Vue），配合状态管理（Zustand/Redux）
- 核心组件：
  - **PPT上传与解析预览**：显示每页缩略图 + 提取出的文本/备注
  - **讲稿编辑器**：逐页文本框，支持插入停顿标记、语气标注（类似SSML）
  - **音色选择面板**：试听、多语言切换
  - **时间轴/字幕对齐器**：拖拽调整每页音频起止时间，可选自动配字幕
  - **预览播放器**：模拟PPT自动播放+配音的效果
- 建议用 WebSocket 或轮询获取异步任务（TTS生成、视频渲染）进度

### 2.2 后端服务层
- API网关：FastAPI（Python）或 Node.js/Express，负责鉴权、限流、任务分发
- 任务队列：Celery + Redis（Python生态）或 BullMQ（Node生态），因为TTS生成和视频渲染都是耗时异步任务
- 微服务拆分建议：
  1. **解析服务**（PPT Parser）
  2. **语音合成服务**（TTS Orchestrator）
  3. **合成渲染服务**（Compositor / Renderer）
  4. **存储与文件服务**

## 三、核心功能模块详解

### 3.1 PPT解析模块
**输入**：用户上传的 .pptx 文件
**输出**：结构化JSON（每页的文本、备注、版式、图片位置等）

技术选型：
- **python-pptx**：读取每页 `slide.shapes` 的文本框内容，读取 `notes_slide` 备注文本
- 若PPT里备注为空，可选：用OCR/规则从正文文本自动生成讲稿草稿（也可以直接调用LLM根据标题+要点生成讲解稿，作为"一键生成讲稿"功能）
- 解析出的JSON结构示例：
```json
{
  "slides": [
    {
      "index": 1,
      "title": "市场概况",
      "body_text": "2025年市场规模达到...",
      "notes": "大家好，今天我们来看一下市场概况。首先...",
      "images": ["shape_id_3"]
    }
  ]
}
```

### 3.2 讲稿生成/编辑模块（差异化功能点）
这是相对Murf AI的一个可以做出差异化的地方：
- **自动生成讲稿**：如果用户没写备注，调用LLM（如Claude API）根据标题+正文要点自动生成一版口语化讲稿，用户再校对
- **SSML/停顿标记**：支持在讲稿里插入 `[停顿1s]`、`[强调]` 等标记，转换成对应TTS引擎支持的SSML标签
- **多语言翻译**：一键把中文讲稿翻译成英/日/韩等语言，再分别配音（做国际化培训场景很有用）

### 3.3 TTS语音合成模块
**多引擎适配层**是关键设计——不要绑死一家TTS供应商，做成可插拔架构：

| 引擎 | 特点 | 成本 |
|---|---|---|
| edge-tts（微软免费） | 免费、中文效果不错，适合MVP阶段 | 免费 |
| Azure Cognitive Services TTS | 商用授权、稳定、SSML支持完整 | 按字符计费 |
| ElevenLabs | 音质天花板级别、支持声音克隆 | 较贵 |
| 火山引擎/阿里云语音合成 | 国内中文场景优化好、备案合规 | 按量计费 |

架构建议：定义统一接口 `TTSProvider.synthesize(text, voice, ssml_options) -> audio_file + duration`，后端根据用户选择的引擎路由到对应实现，方便后续扩展和成本优化（比如免费版用edge-tts，付费版用ElevenLabs）。

### 3.4 音视频合成/导出模块
这是整个产品的技术难点，分两种导出路径：

**A. 导出"带语音的PPT"**
1. 用 `python-pptx` 把生成好的每页mp3插入对应slide
2. 设置音频属性：`自动播放`、`放映时隐藏图标`、`跨幻灯片播放=否`（每页独立）
3. 同时设置幻灯片切换的"排练计时"，让每页停留时间等于该页音频时长，实现真正的自动播放效果（这一步要写入 `slideTiming` XML节点，python-pptx原生不完全支持，可能需要直接操作底层XML）

**B. 导出MP4讲解视频**
思路：PPT本质是"图片+配音"的合成，实现路径：
1. 用 **LibreOffice headless模式**或 **Aspose.Slides** 把每页PPT渲染成高清图片（PNG）
2. 用 **FFmpeg** 把每张图片按对应音频时长拼接成视频片段：
   ```
   ffmpeg -loop 1 -i slide1.png -i slide1.mp3 -c:v libx264 -t <audio_duration> -pix_fmt yuv420p slide1.mp4
   ```
3. 用FFmpeg的concat功能把所有片段拼接成完整视频
4. 可选：叠加字幕（用讲稿文本生成.srt字幕文件，FFmpeg一并烧录或作为软字幕轨道）
5. 可选：加转场动画（如果要保留PPT原生的动画效果，可以考虑用无头浏览器+PowerPoint在线渲染，或用商业SDK如Aspose.Slides直接导出动画视频，技术复杂度更高，建议MVP阶段先不做动画保留）

```
     ▼

     │              │
     ▼              ▼
 导出.pptx      导出.mp4
     │              │

            ▼

            │
            ▼

```

## 七、关键技术难点与应对

1. **音频与画面时长对齐**：每页停留时间必须等于该页音频时长，MVP阶段直接用音频时长驱动切页；进阶阶段做可视化时间轴支持手动微调。
2. **PPT动画保留**：原生python-pptx+LibreOffice方案很难保留PPT里的进场动画/切换特效，若要保留，需考虑：
   - 用真实PowerPoint（Windows Server + Office自动化/COM接口）渲染，成本高但效果最好
   - 或用商业SDK Aspose.Slides for Python，直接支持动画导出为视频
3. **中文TTS自然度**：中文语气词、停顿、多音字是中文TTS的常见痛点，建议引入SSML标记 + 用户可试听调整的机制，而不是全自动黑盒生成。
4. **成本控制**：TTS调用是主要变动成本，建议按用户等级（免费/付费）路由不同TTS引擎，控制毛利。

## 九、一句话总结

整个产品可以拆成四个核心服务——**解析、讲稿、语音合成、音视频渲染**——用异步任务队列串联起来；MVP阶段用免费开源工具（python-pptx + edge-tts + FFmpeg）快速验证闭环，跑通后再逐步替换成更高质量的商业TTS引擎和渲染方案，同时把"讲稿智能生成"和"多语言配音"作为相对Murf AI的差异化卖点。
