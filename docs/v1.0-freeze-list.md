## B. Experimental 保留（不升不降，理由公开）

| 名称 | 文件 | 当前理由 | v1.0 后演化 |
|---|---|---|---|
| `ChartWorkbookBuilder` | `chartbook.go` | 适配接口，1.0 内可能新增方法（如 `Close()`、`Validate()`）；第三方扩展点 | 1.x 中视使用面调查决定是否升 Stable |
| `ChartDataBook` | `chartbook.go` | 数据快照结构，可能随 WorkbookBuilder 接口扩展而加字段 | 视 WorkbookBuilder 演化而定 |
| `DefaultWorkbookBuilder` | `chartbook.go` | 默认实现，受限最小（无公式/命名范围），后续可能扩字段 | 1.0 后扩字段不影响用户代码（不依赖的字段） |
| `CustomPropertyKind` | `docProps.go` | OOXML 变体枚举，可能新增 iota（lpwstr/bstr/filetime 等） | 1.x 增 iota 不破坏兼容性 |
| `CustomPropertyValue` | `docProps.go` | 多字段 union，未来可能重构为按 Kind 类型分流 | 1.x 重构时需 deprecate 与迁移路径 |

**审阅要求**：每项 Experimental 必须在 godoc 给出**演化边界**（"1.0 内可能加 X"），防止静默放宽。**评审期：T-2 周一次性确认**。

## C. API 默认级（122 个）按类别聚合评审

> **2026-09-10 修订**：原"149 个"基于评审开始日统计；T-2 周首批加 Stable 标注 28 个后，API 默认级减少至 122。下方各子类（C.1–C.17）数量按原统计列示，T-1 周评审窗口逐项核对（多数子类的"约 X 个"本就为估值；本节先维持原估算，待评审收敛后精化为定值）。

逐符号评审成本过高；按类别聚合处理。每类给出"维持 API 还是升 Stable"的建议，列例外。

| `GroupShape` / `OpaqueShape` | 对象模型 | API | 同上 |
| `PictureShape` / `PictureSpec` | 对象模型 / 输入 | API | 1.0 前可能加 fit 新枚举 |

### C.3 输入规格 *Spec（建议维持 API）

约 25 个 `*Spec` 类型（`TextBoxSpec`/`AudioSpec`/`VideoSpec`/`ChartSpec`/`FieldSpec` 等）：结构字段均开放为可选（带零值兜底）。逐项维持 API，1.0 内可在不破坏现有默认值前提下增加字段。**无例外**。

### C.4 函数式选项 *Option（建议维持 API）

`NewOption` / `OpenOption` / `SaveOption` / `ValidateOption` / `ReplaceOption` / `BindOption` / `MergeOption`（在 `options.go`）—— 7 个类型，加对应的 `With*` 构造器。**建议维持 API**：1.0 内可在不破坏现有 With* 的前提下增加新 With* 与对应 Options 字段。**无例外**。

### C.5 只读报告 *Report / *Info（建议维持 API）

约 12 个报告类型（`ReplaceReport` / `BindReport` / `SaveReport` / `TimingSyncReport` / `CapabilityManifest` 等）：read-only 输出结构，1.0 内可能增加字段以反映新增诊断信息。**无例外**。

### C.6 值对象 Point / Rect / EMU 等几何与单位（建议升 Stable）

`Point` / `Rect` / `EMU` / `Quad`（`geom.go`）：基础几何单位与坐标，**大量下游代码会用到**——建议升 Stable。`CapabilityManifest` / `CapabilityManifestSource` / `CapabilityDimension` / `CapabilityFeature` 单独成组（与 Output 契约相关）。

**已加 Stable 段落 ✓（2026-09-10）**：`EMU` / `Point` / `Rect` / `Quad` 四类均在 `geom.go` 加 `// Stable:` 段落（不变量 + 1.x 仅追加字段的承诺）。

### C.7 样式与格式解析（建议维持 API）

约 20 个：颜色（`ColorSpec` / `ParsedColor` / `ColorTransform`/`ResolvedColor`）、字体（`FontSize` / `FontProperty` / `FontStyle`/`ResolvedFont`/`ThemeFontSlot`）、段落（`ParagraphProps` / `Spacing` / `BulletKind`/`TabStop`）、Run（`RunProps` / `RunSymbol`）、样式矩阵（`StyleMatrixRef`/`MatrixRefKind`）等。**建议维持 API**：1.0 内可能加新属性对应新增 CSS/OOXML 字段。**无例外**。

### C.8 表格样式（建议维持 API）

约 15 个：`TableStyleFlags`/`StyleToggle`/`StylePart`/`CellFill`/`CellBorder`/`CellText`/`EffectiveCellStyle`/`CellBorders`/`FillKind`（同表+fill info 共享）—— 表格主题字段量大，1.0 内可能扩字段。**无例外**。

### C.9 媒体与音视频（建议维持 API）

`AudioSpec`/`AudioRole`/`AudioShape`/`AudioProfile`/`PlaybackSpec`/`VideoSpec`/`VideoRole`/`VideoShape`/`VideoProfile`/`MediaSource`/`PictureFitMode` 等—— 跟随媒体功能扩展。**无例外**。

### C.10 替换与合并策略枚举（建议升 Stable）

`ReplaceMode` / `MergePolicy` 等少量枚举值（字符串方法、绑字 iota）—— 枚举值一旦暴露给用户做 case，应确保不会再新增/重命名（否则破坏 switch 完备性）。**建议升 Stable**。具体类型：

- `ReplaceMode`（`replace.go`）—— **已加 Stable 段落 ✓（2026-09-10）**
- `ReplaceHit` / `ReplaceResult`（`replace.go`）—— API（结构可扩展）
- `MultiCellTextPolicy`（`table.go`）—— **已加 Stable 段落 ✓（2026-09-10）**

### C.11 布局 / 节 / 诊断（建议维持 API）

`LayoutReport` / `LayoutSection` / `LayoutEmbeddedFont` / `HandoutMasterInfo` / `KinsokuRule`（`layoutdiag.go`）—— 1.x 可能新增节诊断字段。

### C.12 替代与转场（建议维持 API）

`TransitionSpec` / `TransitionType` / `FadeOptions` / `CutOptions` / `SplitAxis` / `SplitDir` / `TransitionSpeed` / `TransitionDir`—— 转场类型枚举可能在 1.x 增；选项结构字段多。**建议维持 API**。

### C.13 时序同步（建议维持 API）

`TimingSyncOptions` / `TimingSyncReport` / `TimingPlan` / `PageTiming` / `TrackContribution` / `UnknownDurationPolicy` / `AnimationTimingPolicy` / `PlaybackTrigger` / `IconMode` —— 实验性领域，1.x 与实验同步。

### C.14 图表详细（建议维持 API）

`ChartType` / `ChartSeries` / `ChartData` / `ChartSpec` / `ChartDataLabel` / `ChartErrorType` / `ChartErrorBars` / `ChartTrendType` / `ChartTrendline` / `ChartAxisOptions`（chart.go / chartadv.go）—— 图表建模领域大，1.x 可能扩字段。**无例外**。

### C.15 几何细节（建议维持 API）

`GeometryInfo` / `GeometryKind` / `GeomAdjust` / `GeomGuide` / `GeomPath` / `PathCommand` / `FillInfo` / `GradientFill` / `GradientStop` / `PatternFill` / `BlipFillInfo` / `EffectInfo` / `Effect` / `EffectKind`（`geomadv.go`）—— 几何引擎部分大，1.x 必扩字段；**维持 API**。

### C.16 创建与克隆策略（建议维持 API）

`ClonePolicy`（`clone.go`）—— 多档策略，1.x 可能加新档；**维持 API**。

### C.17 核心属性（建议维持 API）

`CoreProperties` / `CorePropertiesPatch`（`docProps.go`）—— Dublin Core 字段，1.x 不会扩（标准固定），但用户对字段顺序、扩展 Dublin 路径有期待，**维持 API** 即可。

## D. 评审 checklist

每条 PR 增加新导出符号时，**自动**进入本清单"待评审"区。一周内由至少一位 OWNER 决档。

| 决策 | 要求项 |
|---|---|
| **升 Stable** | ① 给出"为什么 Stable"理由（不变量表述）② 列出 1.0 后不允许扩展的方向 ③ 提供 ≥1 处现使用面举例 |
| **维持 API** | ① 默认决策，无需理由 ② 1.0 锁字段前可调整 |
| **保留 Experimental** | ① 给出"为什么 1.0 可能改"的具体方向 ② 列出未来 Stable 化的时间窗 |
| **降档（Stable → Experimental）** | ① 禁止走 PR 直降，必须**新建 ADR** 走评审 ② 跟踪文档 §"破坏性变更公告"段登记 |

## E. v1.0 锁定流程（执行清单）

**T-2 周**（启动，今日起 14 天）：

1. 本文档进入"评审中"状态，开放模块负责人标注

**T-2 周 ~ T-1 周**（评审窗口）：

3. 错误/诊断契约（§A.1/A.2/A.3）逐项加 `// Stable:` 段落注释

7. PR 暂停接受"动字段"类变更
8. 只接受"加字段"、"加 godoc 段注释"类 PR

**T-3 日 ~ T-0**（冻结与发布）：

9. 跟踪文档 `docs/go-pptx-实施状态跟踪.md` 顶部新增"v1.0 冻结通告"段

**T+0**（发布）：
