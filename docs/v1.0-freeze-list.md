## D. 评审 checklist

每条 PR 增加新导出符号时，**自动**进入本清单"待评审"区。一周内由至少一位 OWNER 决档。

| 决策 | 要求项 |
|---|---|
| **升 Stable** | ① 给出"为什么 Stable"理由（不变量表述）② 列出 1.0 后不允许扩展的方向 ③ 提供 ≥1 处现使用面举例 |
| **维持 API** | ① 默认决策，无需理由 ② 1.0 锁字段前可调整 |
| **保留 Experimental** | ① 给出"为什么 1.0 可能改"的具体方向 ② 列出未来 Stable 化的时间窗 |
| **降档（Stable → Experimental）** | ① 禁止走 PR 直降，必须**新建 ADR** 走评审 ② 跟踪文档 §"破坏性变更公告"段登记 |

**决策依据**：

1. **Capability Output 契约族** —— §A.3 的 `CapabilityStatus` 单独 Stable
   但 Capability manifest 整体仍 API 默认——下一份 manifest 升级到大版本号
   时所有字段都被波及。T-1 周合并评审后将整个 Output 契约族（4 类型 + 2
   常量）一次性锁定，与 `CapabilityManifestSchemaVersion` 的大版本号轴
   形成"代码契约 + schemaVersion 双重稳定边界"。
2. **句柄 ID 类型** —— `SlideID` / `ShapeID` 是用户接触 OOXML sldId@id 与
   ShapeID 的契约入口；底层 u32 + 文档语义锁定后，用户做 ID 比对、事件
   关联、跨调用序列化时无需关心内部实现。

**不升 Stable 候选与理由**：

- §C 各子类的 `*Spec` / `*Option` / `*Info` 输入规格族：v1.x 内可能加
  字段以对应新增样式/属性——按 ADR-015 §"API 默认"承诺增量扩展。
- `ActionLogEntry` / `ActionLogReport` 等操作日志条目：可能加新 Stage /
  新字段反映新增诊断。
- §A 错误码集合段：上一批已加 Stable 段落（17 个）——T-1 周无新增。

下次评审（T+0 准备窗口）候选：`ActionLogEntry` Stage 枚举、`ValidationIssue` 错误聚合结构（如已导出）等。
